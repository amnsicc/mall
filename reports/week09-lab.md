# 第 09 周实验报告：Element Plus

日期：2026-11-09。基础项目为本仓库第 08 周完成态。

## 完成内容

1. 使用 pnpm 安装 Element Plus、图标和两个 unplugin 自动导入插件。
2. 配置组件、函数式消息 API 和指令按需导入，通过 CSS 变量设置绿色主题，实验页 `/ui-lab` 单独验证局部蓝色主题。
3. 后台使用 Layout、Menu、Table、Pagination、Empty 和 Loading。菜单跟随路由高亮，商品名称与分类可以筛选。
4. 商品新增与编辑复用一个 Dialog；Form 校验名称、分类和正数价格；保存与删除通过 API 方法；删除取消静默退出。
5. 完成订单表格、分页、登录表单和密码显示/隐藏。顾客导航不展示课程实验和后台入口。

## 结论一：全量与按需引入的构建体积

测量发生在案例 1 完成时。两次使用同一份源码、同一构建配置，差异仅为全量方案额外注册整个 Element Plus 并引入完整 CSS。统计所有 JS/CSS chunk，不含图片；gzip 分别压缩各 chunk 后求和，不等同于首页首次网络传输量。

| 方案 | JS 原始字节 | CSS 原始字节 | JS gzip 字节 | CSS gzip 字节 |
| --- | ---: | ---: | ---: | ---: |
| 全量 | 1,041,713 | 436,738 | 339,976 | 62,466 |
| 按需 | 305,295 | 76,568 | 114,900 | 14,512 |

原始记录：[bundle-measurements.json](./bundle-measurements.json)。复测命令：`pnpm measure:bundles`。后续新增表格与弹窗后再运行，会测到新版本的体积，不应拿来冒充案例 1 的历史数值。

结论：按需导入只打包实际使用的组件和样式，能减少体积。代码仍要设计好数据流，组件库不会替代筛选与分页逻辑。

## 结论二：实际遇到的问题

将表格接到接口后，测试脚本在筛选请求完成前寻找「编辑」按钮，匹配到了五个按钮，无法确定要编辑哪一行。界面无异常，这属于验收脚本定位和等待条件不明确。

修复：先通过实际商品名称定位目标行，再在该行中定位编辑或删除按钮；异步状态通过元素出现、响应或 DOM 条件等待，不靠猜测执行顺序。

另外，新增弹窗每次先清空所有字段，再写入初始值，最后清除校验状态，避免编辑后再新增时残留 id、stock、img 和错误提示。

## 结论三：解决与预防

- 表单使用 `validate()`，验证失败时停止，不发送写入请求。
- 删除确认与删除请求分别处理异常，取消操作不显示错误消息。
- `v-loading` 通过 `ElementPlusResolver({ directives: true })` 导入，加载结束在 `finally` 关闭。
- 筛选或每页数量变化时回到第一页；删除最后一页记录时修正页码。
- 只保留一套 UI 库；后台主题使用公开 CSS 变量，顾客页面背景保持纯白。
